## 总览：一句话版

- **01 横评**：五方案（KVMem/LMCache/Mooncake/vLLM/SGLang HiCache）中只有 KVMem 走「全历史保留 + 内容检索召回」而非前缀复用命中率路线；唯一单机、无 daemon、无 RDMA、显存预算写成可声明契约（B+R）的方案。`prepare→spill→publish` 事务 + 逻辑地址/物理位置解耦是五者中唯一成文契约。局限：无跨进程共享、无分布式编排、检索 query 只取末尾 ≤512 tokens、无官方基准数字。
- **02 patches**：实算 **104 个 patch**（llamacpp 5 / ninfer 48 / polystrata 22 / radiance 29）。四后端两种集成机制：前三者走 `versions.json` 哈希链（75 个，sha256 + requires 串行依赖 + after_tree 树哈希双层校验），radiance 走 `backends/radiance/adapter/` + `prepare_native.py` 独立管线。最大补丁 `ninfer-layerwise-recall`（+14585/−550，134 文件）：整窗召回→逐层工作集，是显存工作集能压小的关键。开洞次序（ninfer 实证）：配置→页池计量→桥接（只借不建）→统计→快照→共享→投机→逐层化。
- **03 spread**：跨会话检查点复用的正确性**不靠 key**——`prompt_cache_key` 降级为纯诊断元数据，判定走内容 proof 链（exact 前缀 + media/position identity + `accepted_through==frontier` + stamp + KV 页覆盖 + checksum）；restore 恒 fork 新分支、源不消费。代价实数：普通请求 SSD 回退税 +36.6%/+59.6%，收益集中 middle edit −28~−30%。
- **04 实验**：分环境 GO/NO-GO 见下表。最大阻塞 = Linux 无预编译 KVMem worker（必须源码构建）+ 无公开 Qwen3.5-4B `.ninfer`（需自行转换：ModelScope 有 unsloth/Qwen3.5-4B-MTP-GGUF，转换器 `python3 -m tools.convert --recipe qwen3_5_dense_gguf --device cpu`）。Kaggle P100 sm_60 硬性 NO-GO（上游 gpus.md:26）；T4（sm_75）GO-条件（首跑=首次物理实机验收）。指标采集面齐全（decode tps / snapshot_hits+reused_tokens / VmRSS）。
- **05 Radiance**：上游 = Codeberg **StillDeadcode/radiance**（独立 AMD C++/HIP 引擎，非 fork）；补丁 33 个三代，最大 `radiance-1.17-kvmem.patch` 6780 行。跨 ISA 结论：公共契约层是纯 C++17 host 库（六步适配硬件无关、零 GPU 代码）；真正增量仅六项（设备桥/状态导出 ABI/执行生命周期/内存可访问性/TP 模型/统计 hooks），最重的是「引擎要有可挂钩的执行边界」。
- **06 引擎物理层（新增）**：页大小 64 是**编译期常量**（`paged_kv_cache.h:20` + `paged_kv_address.cuh:8-13` 的 `static_assert`，decode 用 `position>>6` 取页号）→ 改 block size = 重编全部 kernel，这就是「固定 64」的真因。预算 B 的**唯一强制点**是 `paged_kv_cache.cpp:463-482` `cover()`，四个计数器 `capacity - lent - loaned - allocated` 全要算对；不足先调 `recall_` 抢回 loaned。`materialize` 的连续性偏好不是优化而是**可借性前提**（VMM 只能 unmap 连续 run）→ 分配策略直接决定多少内存可借。lend/loan 两种强度，loan 上限 = `unpromised_free_pages()`（空闲减去未来必物化的预留）。零拷贝的全部理由浓缩在「**free 页写前不读**」一条不变量，它同时支撑可借性与 suspend 快照瘦身。附带 Windows/WDDM 硬雷：pinned host 计入显存预算，host KV 被夹到 `(free_device−1GiB)/2`。
- **07 引擎上层（新增）**：一页挂两个副本（device/host）+ **8 个正交计数**（epoch / committed_columns / references / active / writer / protected / source_pins / destination_pinned）。**epoch 必须配 committed_columns 双字段**——页可部分填满，"epoch 相同"不足以保证副本可用，这是 03 号「内容 proof 链」的引擎级根据。谓词/动作分离（`can_*` 全 noexcept、动作全 throw），noexcept 路径遇不可能状态用 `terminate` 而非抛。suspend 有 **7 道前置门**（含每 rank 每条 stream 同步、loan 必须在 capture 前 recall_all）。快照绑定精确到 RoPE profile（旋转每个 key）与 plane_digest（两个 TP 切法可有相同 plane 数不同 stride）；完整性用 word-wise 哈希，理由写得极准——「威胁是位翻转不是篡改」。租约走**阶梯 + 算术判**（不拿异常当控制流），两池「全做或全不做」靠先成功者主动退回；**空间不足时 settle 而不是 fail**，同时记下欠账。最反直觉一条：压力启发式**不许把自己的响应当成新输入**，否则会对零缺口维度凭空制造压力、把策略推向不必要的销毁。
- **08 prefix 层（新增）**：块身份是五元组 `parent/hash/extra/tokens`——**hash 只找候选，64 个 token 原文才是判等证据**（每块落盘 284 字节，其中 256 是 token），这是「拿存储换可验证性」的明确取舍。`extra`（vision/lora）是**前缀累积量**：一张图会污染它之后所有块，这是 RadixAttention 语义的必然。种子是 ASCII 拼的模型名（`0x6e696e666572`="ninfer"）。`frontier ≡ 64×(anchor深度+1)+tail.size()` 是结构恒等式。**Host tier 是统一 slab 池，块与 StateImage 抢同一批字节、不分固定配额**（这会给 04 号计划的 B×ctx 扫描引入未预料的交互项）。文件布局「表在前、slab 在后」使小 tier 能只读被选中的 slab（`bytes` 不计 seek 越过部分）。保存 = 临时文件 + rename，取消点选在 slab 之间且**最后一个 slab 之后取消仍保留旧文件**；加载级联跳过（父缺则子与 snapshot 全跳），任何异常 `clear()` 全清。装不下时的选择 = **去掉时间基的 GDSF 密度贪心**（`(1+hits)×max(0,saved)/size`，平局按 frontier 降序，装不下 `continue` 不 `break`，且只为被选 snapshot 的路径选块 → 无死块）。**KVMem 的真增量因此可精确定位**：NInfer 原生已有 host KV/块身份/GDSF 驱逐/落盘，KVMem 换的是三个策略决策——有界→无界、前缀命中→内容检索召回、独占文件→跨会话共享；补丁之所以要 +16651，是因为必须拆掉所有围绕「有界」假设建的补偿机制（settle 降级、restore 贪心、几何与预算校验）。
- **09 磁盘层（新增）**：身份模型 = **每 frontier 一个 128 位滚动摘要**（`disk_kv_bridge.h:6-11`），磁盘层已是内容寻址 + 跨会话 dedupe——08 号「跨进程共享」的表述据此修正：KVMem 的真增量是「无界 RetainAll / 内容检索召回 / Host RAM 层跨进程共享（从 L3 上移到 L2）」。摘要双射混合（splitmix 双乘子 + ASCII 域字 "ninfer-r/v/l" 自定界防串接歧义），实测 **10 ms/admission @ RTX 5060 Ti（2026-10-28）**——word-wise 比字节级 FNV-1a 省 8 个依存乘法。摘要只作短名单，token 原文判等。**positioned I/O 不用 mmap**：store 大于内存时 mmap 逐页 fault，满盘写 sparse slot 会 SIGBUS 而 pwrite 只返回错误。预算 65/25/10 固定配额（与 Host tier 统一池相反——L3 只有 LRU 时间戳、无法跨类比价值）。写路径**不许留洞**（restore 遇第一个缺页即停）；恢复 32 页/批 + **8 s 死线**（比重算慢就放弃）。
- **10 准入合并（新增）**：准入是**报价**不是判定——五态出口零拒绝（Ready/Blocked-兄弟物化中/Blocked-装不下/递归重报价）。合并延后必须建立在「本可立即满足」之上（`fits(nullptr,{})` 先行）防死锁。`fits()` 的自洽会计把「本次准入自己要 pin 的路径块」从可驱逐池里扣掉——朴素写法会算出自吃自己的假可行。三条排除谓词：块未填满 / vision 占位严格双侧 / root 快照对带 LoRA 的请求不可见（**引擎把自己的设计盲点写在决策点旁边**）。跨请求合并 `hybrid_await_sibling` 的经济判据 `saved > cost && predicted ≤ coalesce_wait`，预测乘 2（其他 lane 的 decode 轮次插队）；等到的快照标 `boundary=true` = **引用计数式撤销权**，否则合并造出的快照会被先来者的 supersede 立刻收回。**命中缓存必须进公平性核算**（`units = 1+(suffix-1)/chunk + vision 项 + 输出项`），否则缓存请求按未命中成本占份额。
- **11–15（新增）**：**11 StateImage**：**KV 页可以按列补齐（07 号 `committed_columns`），StateImage 要么完整要么不存在**——所以它要独立的身份/副本/转移机制。三个平面（逻辑身份 ≠ 副本）、四态角色机、两把锁（`source_pins`/`destination_pinned`）、fork 三段式（begin/commit/abort）、三种转移方向（第三种是 Both 源的零拷贝分身份）、`publish_transfer(keep_source_replica)` 一个开关决定提升还是复制、副本只能丢「另一份还在」的那份；**单流 FIFO 换掉了依赖图**。**12 租约阶梯**：四级降级链（扩租约→settle→抢保留缓存→缩答案预算），任何一级都不许 launch 失败；`target()` 三重 clamp 的注释明写「so the reservation can only fail on space」——失败归因设计；**被扩展者不能成为扩展者的受害者**（排序保护）。**13 磁盘 spill**：主链页边再存一份（页内边界双写，写放大最多 5×/页）为可恢复性付费；`kSpilledAnchors=3` 取最早三个（后续轮次重新 render，生成文本内部边界对不上）。**14 落盘格式**：表前置使小 tier 只读被选中 slab；`save` 用 `file_index.at(parent)` 强制 parents-first；尺寸恒等式不读 footer 就能判截断；load 失败 `clear()` 全清且连 `required_host_bytes` 也清（避免调用方据残值建议加大 tier）。**15 stage_plan**：`stage_fits` 纯整数运算零 CUDA 依赖——**容量是算术不是测量**，这是 16 号报告的方法论地基；`crosses_after` 每 stage 边界恰好一个使层切分对慢链路容错。
- **16 容量算术（新增）**：从 `.ninfer` manifest 逐张量反推权重 + GDN state，零 GPU 算出全卡容量表。**两套口径**：stage 预算口径（9 层单价含 MTP + fixed 3134.73）喂 `stage_fits`；容量口径（8 层不含 MTP + persistent）喂 `--kv-capacity auto`，6 GB bf16 = **928 页 = 59,392 token**。**九档 KV dtype** 编译引擎源码实测 B/token/head（BF16 1024 / INT8-G64 528 / NVFP4-G16 288…）。自我纠错三次全靠「拿总数撞另一个独立分母」：权重多算 308 MiB（`parts[].range` 是元素数不是字节）→ 6GB 容量偏大 17%（MTP 漏算）→ 全部 KV 数字 2 倍错（`physical_bytes_per_token_head()` 是 K+V 各一遍）。
- **17 Phase B 解卡（新增）**：把问题从「拥有资源」改写成「购买执行」。逐 arch **编译+运行**实测：`sm_75: OK`、其余 FAIL——**编译成功不是可运行性证据，加载执行才是**。`nvcc -arch=sm_86` 在 T4 上能编译，运行才报 `no kernel image is available`。依赖三件套 meson/ninja/nasm + CUDA 13 的 `CUDA::cuda_driver` 要 `CMAKE_PROJECT_INCLUDE` shim（真路径用 `ctypes.CDLL("libcuda.so.1")+maps` 问 loader，`find` 只命中 Julia `.jl`——**扫目录会得出错误结论，必须先问 loader**）。
- **18 Phase B 实跑（新增）**：v5 全绿（4.41 h build + 9 行扫描）。容量三行预测全错（+23.9%/+23.3%）但**差判据活、绝对判据死**——预测 512/1024 差 455 页，实测 256，比值 0.5626 ≈ 2.00/2.25 直接指出单价错。四项误差精确闭合：ECC −960 / stage +1536 / resident 漏 623.8 / headroom 双扣 +1024。`m=128` 零成本钉死：v5 的 explicit 行 `32768→512 页` 证明 `resident_main_pages=0`，字面值 `max(page_count(8192),1)+0=128`。**`if headroom:` 对 0 为假**——Python 可选参数最常见静默 bug，凡传可选参数必须在产物里回显实际生效值。Host tier 六行形状全中；`device_state_slots` host=0→4（C+2）、host>0→3（C+1）是 spec §5.4 在 base 上的首次实测。
- **19 hybrid 生命周期（新增）**：接 10 号读 `hybrid_program.cpp:1174-1610`。发布前沿 = 三池交集（`text_kv_valid ∩ backend_kv_valid ∩ ledger.size()`）；DFlash2 ring 归 StateImage 故不约束块发布。**release 的顺序是命门**：`start_block_host_writes` 必须在 `index.release_path` 之前，否则驱逐只丢 Device 副本而丢节点。supersede 两道门；disposable 快照永不因自己前进而收回。endpoint 十道门 + 先确认 `kv_releasable` 再转移 image 所有权（转移后只能走不返回失败的 strict 路径）。统计面有 **3 个丢数计数**（`host_snapshot_evictions`/`host_dead_reclaims`/`unbacked_node_losses`）——04 号矩阵该采的后三者在 v5 只验了形状。
